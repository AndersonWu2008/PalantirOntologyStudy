# 07 — 唯一事实如何下载

## 思考

第一次碰到「可以从网上下载」的东西。在 Foundry 里这叫 **Source + Sync + Pipeline**，不要做成 Object type「下载任务」除非你要运维检索作业失败（那是平台监控，不是交易 Ontology）。

A 股日频会话从哪来（本仓库现状）：pytdx / 腾讯实时等。 Palantir 要求：**多个供应商合并进同一 DailyBar**，不要 `TencentBar` 与 `TdxBar` 两个 object type（System Silos）。冲突规则写在 pipeline（例如：收盘后官方日线覆盖盘中腾讯快照）。

## 下载过程（逐步，不跳）

1. **交易日历**  
   需要知道「今天是不是交易日」。来源：交易所日历或可靠节假日表 → dataset `calendar_ashare` → 生成/更新 TradingDay 对象（先有日期，盘后才有广度）。

2. **证券主数据**  
   代码、简称、板块、交易所、上市日、ST、股本。来源：行情商证券列表 + 公告。→ dataset `securities` → Stock / Company / Exchange。**先有 Stock，再下 K 线**，否则 456 个文件无处挂。

3. **K 线（源会话）**  
   对股票池每个 ticker：拉日 OHLCV、额、换手、涨跌停价。  
   - 增量：只拉日历上缺失的日期。  
   - 落地：Foundry dataset `ohlcv_daily_raw` → 清洗 `ohlcv_daily_clean`（类型、复权政策必须写死：本系统用哪一种复权，全链路同一）。  
   - 映射：一行 → 一个 DailyBar 对象，主键 `ticker:date`。

4. **行业映射**  
   `stock_industry_map.csv` 一类表 → Industry 对象 + `inIndustry` link。不要把行业名当 Stock 字符串。

5. **盘中 vs 收盘**  
   信号 JSON 里写过「腾讯实时」。规则：未收盘的 bar 标记 `sessionComplete=false`（源 Property）。`rankUniverse` 的提交条件：只用 `sessionComplete=true`，或明确接受「盘后快照」并记录 data lineage。禁止把未完成会话当成收盘价写死。

## 停：分类

| 事物 | 判定 |
|------|------|
| 腾讯 / pytdx | **Source**（Foundry 数据连接），不是 Object type |
| 原始落表 | **Dataset** |
| 清洗后一行 K 线 | 映射为 **DailyBar** |
| sessionComplete | DailyBar **源 Property** |
| 「下载今天数据」 | **Pipeline Schedule**（收盘后 cron） |
| 操作员点「立即同步」 | 可选 Action **触发**作业，不把行情写入 Action 参数 |

## 本步需要的过程（已到可执行叶子）

- 网络：供应商接口。
- 鉴权：Source 配置。
- Schedule：每个交易日 15:10 之后跑 sync。
- 健康检查：456 只应到数、停牌允许 0 量、缺失 ticker 报警。**缺数据则不生成「假装完整」的 Signal。**

历史第一次全量：拉 2020 至今（与 部署脚本 样本对齐），再进入增量。

## 技能与校验

- Skill：`research`（字段字典）、pipeline data expectations。
- 校验：主键唯一；close>0；涨跌停价与 board 幅度一致（可用 Function 交叉检验，不一致则源脏，派生全部停）。
