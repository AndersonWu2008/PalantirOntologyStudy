# 06 — 派生指标与唯一事实

## 思考

到这里才允许谈「各种指标」。它们不是目标，是 Signal / 制度 / 风控的**输入**。

唯一事实（本系统）：

- 每只股票每个交易日的 **OHLCV、成交额、换手、涨跌停价、股本**（交易所/行情商给出的会话事实）。
- 历史就是这些 DailyBar 的序列，不是另一份「指标库」。

所有指标 = Function(该股票的历史 DailyBar 源字段，必要时加当日全池)。

**禁止：** 在代码里写死「新宏泰的 RSI=70」；禁止研究 pickle 与线上 Function 两套公式；禁止把因子做成独立 Object type（股票×日×因子会爆炸）。

## 派生如何写回（ Palantir 对齐用户要求）

```
源 Property（close, volume, …）
        │
        │  Function 唯一公式（与 v42/factors.py 同构）
        ▼
派生 Property（ma20, 45 个 factor*, f1–f4 rank, …）
```

- **无人值守：** Schedule 跑 `computeOverlays` → `computeAllFactors` → `computeTurnoverDynamics` → `computeLiveRanks`。这是 Pipeline 调 Function，**不是**交易员 Action。
- **公式变更：** 改 Function → 重跑受影响日期 → 派生 Property 全部换血。这叫血统。旧 Signal 上的 score 快照保留（当时决策），与今日重算可以并存，靠 Strategy.version 区分。
- **Function-backed Action：** 例如提交买单时把 `sizePosition()` 的股数写入 Order。这是决策对象上的派生快照，输入仍是 Account+DailyBar+Strategy。

完整列见 [`../000_Stock_Object_Type/09_indicators.md`](../000_Stock_Object_Type/09_indicators.md)。

## 停：分类

| 事物 | 判定 |
|------|------|
| 一只股票一天的会话 | Object type **DailyBar** |
| open/high/low/close/volume/amount/turnover/limitUp… | **源 Property** |
| ma* / rsi / atr / 45 因子 / 换手动态 / 截面 rank | **派生 Property** |
| computeAllFactors 等 | **Function** |
| 「刷新因子」按钮给研究同学点 | 可以是 **Action 触发重跑**（作业），但 Action 本身不算因子；或只给 Pipeline |
| 因子「动量 1 个月」作为实体 | **不是** Object type |

Kitchen sink 的正确理解：不要把 ETL 时间戳、原始 JSON 堆上 Stock。**交易用得到的指标堆在 DailyBar 上是允许的**，用 visibility=hidden 把研究列藏起来。

## 本步需要的数据

每只股票：**今天的源会话 + 至少 252 个历史交易日的源会话**（12 月动量、200 日上市过滤比这个更长则取更长）。没有历史，派生 Function 会输出空，明天策略必须失败而不是用默认 0（0 是假事实）。

这些源会话从哪来 → 07。

## 技能与校验

- Skill：`tdd`（固定 OHLCV 夹具 → 因子位等）、`research`（对照 `FACTOR_REGISTRY` 45 名）、`diagnosing-bugs`（对不齐时先查是否用了未收盘的 intraday）。
- 校验：任意派生列 `f` 满足 `f == Function_f(源)`；重跑幂等；截面 rank 的输入集合等于当日 Index 成员且有 bar 的集合。
