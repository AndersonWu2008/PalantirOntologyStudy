# 05 — 制度与广度

## 思考

为什么打分前要有「今天是 sideways」？因为 v46 的权重随制度变；熊市不开新仓；bull/hv 要连着两天才开门。

第一个错误：把 `regime=sideways` 写到 456 只 Stock 上。那是同一个全市场事实复制 456 遍，改一处漏 455 处。

第二个错误：交易员每天「选择」制度（Action）。制度是行情聚合出来的，不是意志。Override 可以以后加稀有 Action，默认路径不是它。

正确：一个 **TradingDay** 对象，主键是日期。广度、涨跌家数、制度、连板天数是它的 Property。其中日期是源（交易日历），其余是派生。

## 广度怎么来

定义（卡片）：当日股票池中 `close > ma20` 的比例。

所以它 **不能先于** DailyBar.close 和 DailyBar.ma20。ma20 又不能先于历史收盘价。思维顺序：

1. 先有池内每只当日（及之前 19 日）的收盘价。
2. Function `computeOverlays` 写 `ma20`（派生）。
3. Function `computeBreadth` 读当日 456 条 bar，写 TradingDay.breadth 等。
4. Function `detectRegime` 读广度历史，写 TradingDay.regime、regimeStreak。
5. Function `gateOpen` **现算**（不作为源 Property 落库）。

## 停：分类

| 事物 | 判定 | 种类 |
|------|------|------|
| 2026-10-09 这一天 | Object type TradingDay | |
| sessionDate | Property | 源（交易日历） |
| breadth、涨停家数、medianChange | Property | 派生 |
| regime、regimeStreak | Property | 派生 |
| gateOpen | Function 输出 | 查询时派生；需要审计则快照到 Signal |
| detectRegime / computeBreadth | Function | |
| 「把今天标成震荡」按钮 | 默认 **不是** Action | |

DailyBar 与 TradingDay 的关系是 Link `barOnDay`，不是在 bar 上再存一份 regime。

## 本步需要的数据

- 交易日历（哪些日期是 A 股交易日）— 可下载/可维护的源。
- 当日及历史 DailyBar.close、ma20。
- 股票池（算广度的分母是 456，不是全市场 5000）。

## 技能与校验

- Skill：`grilling`（制度规则是否用了未来日？）、`tdd`（给定一组 close，regime 位相等）。
- 校验：同一 TradingDay 上只有一个 regime；Object Explorer 搜日期能打开这一天，并 Search Around 到 456 条 bar。
