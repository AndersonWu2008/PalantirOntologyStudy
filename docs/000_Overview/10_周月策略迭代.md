# 10 — 周月策略迭代

## 思考

日频系统如果把策略写死在代码常量里，周月升级只能改代码发版，Ontology 不知道「明天用的是哪一版」，样本外评估也对不齐当时规则。

策略迭代的第一性原理：

- **参数与开关** 活在 Strategy 对象上（`version`、`regimeParameters`、`enabled`）。
- **公式** 活在 Function 里。公式变了要升 version，旧 Signal 快照仍可读。
- **评估** 是 Function：在历史 TradingDay 序列上重放 `rankUniverse` + 模拟 Account，**禁止**用未来 DailyBar（前视偏差）。
- **采纳** 是 Action：`EnableStrategy` / `DisableStrategy`，或同一 Strategy 上更新参数（须权限 + 记录谁改的）。

不要新建 `Strategy_v47` **类型**。那是 Time Machine。同一个 object type，新对象或新 version 字符串。

## 迭代工作流（每周/每月）

1. 冻结评估窗口（例：最近 60 个交易日，不含未完成周）。
2. Function `evaluateStrategy` 读当时应可见的 DailyBar（严格 T 只用 ≤T）。
3. 产出评估结果：可作为 **Report 对象**（可选）或 Workshop 仪表盘。若要在 Object Explorer 搜「2026-W40 评估」，再加 object type `StrategyEvaluation`（主键 `strategyId:window`）。v1 可以先仪表盘，不建类型。
4. 若采纳：改参数或启用新 Strategy — **Action**。
5. 次日日频作业自动读 `enabled=true` 的 Strategy。无需改 Pipeline 拓扑。

Generator 改参白名单见 部署脚本 的 `trading-research` skill：一次一处小改。

## 停：分类

| 事物 | 判定 |
|------|------|
| v46 玩法 | Object type Strategy |
| regimeParameters | Property（配置，不是行情派生） |
| evaluateStrategy | Function |
| 启用新版 | Action |
| 每次回测的权益曲线点 | 不要做成数百万 object；用 dataset 或 time series。若只要摘要，评估对象上几个 Property |

## 校验

启用前：样本外闸门（见 14）必须过。生产 Strategy.enabled 在全库至多一条「实盘主策略」（可用约束），避免两个版本同时 `SubmitBuy`。
