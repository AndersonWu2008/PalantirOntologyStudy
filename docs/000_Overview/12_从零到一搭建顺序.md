# 12 — 从零到一搭建顺序（Foundry 施工）

理解顺序是 01→10。**动手顺序相反：先有 Source，才有对象，才有 Action。** 下面按周，每周结束有闸门，不过闸门不准「先做看板装样子」。

## 第 0 周 — 语言与分类

- 读本教程 00–01、`CONTEXT.md`、`docs/000_Stock_Object_Type/`。
- Skill：`brainstorming`、`domain-modeling`。
- 交付：术语表冻结（Stock / DailyBar / TradingDay / Signal…）；明确不做美股。
- 闸门：任意名词能落入五问口诀。

## 第 1 周 — Project 与 Source

- Foundry Project 结构（raw / transforms / ontology）。
- 连接行情 Source、日历、行业映射。
- 交付：能 sync 一张原始 K 线 dataset（哪怕先 10 只股票）。
- 闸门：data expectation：日期、代码、OHLC 非空。

## 第 2 周 — 主数据 Ontology

- Object type：Exchange、Company、Stock、Industry、Index。
- Link：listedOn、issuedBy、inIndustry、constituentOf。
- Pipeline 把证券列表映射上去。
- 闸门：Object Explorer 能搜到 `000001.SZ`，Search Around 到交易所和行业。**此时还没有买卖。**

## 第 3 周 — 行情对象

- TradingDay、DailyBar、hasDailyBar、barOnDay。
- 全量历史进干净 dataset，映射对象。
- 闸门：选一只股票能列出 DailyBar；主键无重复。

## 第 4 周 — Function 与派生 Property

- 实现 computeOverlays / computeAllFactors / 换手动态，写回 DailyBar。
- 测试：夹具位等。
- 闸门：任意派生列可指出 Function；重跑幂等。

## 第 5 周 — 截面、制度、信号

- computeLiveRanks、computeBreadth、detectRegime、rankUniverse。
- 物化 Signal。
- 闸门：某一天的 TradingDay 上能看到 breadth 与 regime；当日 Top Signal 能链到 Stock。

## 第 6 周 — 账本与 Action

- Account、Position、Order、Fill、Strategy。
- Action：Approve、SubmitBuy/Sell、Close、Pause。
- Function-backed：sizePosition、preTradeRisk 作为提交条件。
- 闸门：用模拟账户走通「批准→下单→假 Fill→Position」；行业上限能挡住第三只银行。

## 第 7 周 — 日频 Schedule 与早盘 Workshop

- 收盘后作业链。
- 早盘看板：今日制度、门控、信号表、持仓建议。
- 闸门：断网式演练——源数据缺 10 只则 **不发**「完整信号」，发警报。

## 第 8 周 — 回测账户与迭代 Action

- 第二 Account 跑 evaluateStrategy。
- Enable/Disable Strategy。
- Skill：`trading-research`、`grilling`、`tdd` 前视检查。
- 闸门：评估 Function 无法读到窗口期末之后的 bar。

## 之后

扩到 456 只、实盘券商 Source、监控。类型不再膨胀，只加实例与 Schedule 可靠性。
