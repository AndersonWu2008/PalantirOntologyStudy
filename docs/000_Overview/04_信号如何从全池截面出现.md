# 04 — 信号如何从全池截面出现

## 思考

Signal 从哪来？若交易员手写「今天买新宏泰」，Ontology 只是备忘录， Palantir 的价值（同一事实、可复盘、可迭代）全部丢失。

日频目标要求：T 日收盘后，对 **股票池内每一只**（456）用**同一套 Function** 打分，按制度加权，过滤涨停与门控，**物化**为 Signal 对象（至少 Top N，或全池带 rank）。

「物化」有两种 Palantir 做法，本教程两条都承认，但日频早盘卡选第一条：

1. **Pipeline / 作业调用 Function `rankUniverse`，创建当日 Signal 对象**（无人值守）。创建对象不是交易员 Action；交易员 Action 是事后 Approve。
2. 查询时 Function 返回 object set，不落库 — 无法批准、无法把「当时第 3 名」当历史。

因此：Signal **类型**是 Object type；**每日实例**由调度作业根据公式生成；**批准**才是 Action。

## 评分依赖（仍不谈如何下载 K 线）

v46 卡片（`STRATEGY_CARD_V2`）需要：

- 每只股票当日：涨跌幅、量比、ATR、成交额 — 来自 DailyBar（源 + 已派生）。
- 这四个量在 **456 只里的百分位** — 必须全池一起算（Function `computeLiveRanks`）。单只算不出 rank。
- 制度权重 — 来自 TradingDay.regime + Strategy.regimeParameters。
- 门控 — Function `gateOpen`。门控关时仍可生成 Signal 供观察，但 SubmitBuy 失败。

## 停：分类

| 事物 | 判定 |
|------|------|
| 一张「2026-10-09 新宏泰 91.7 分」 | Object type **Signal** |
| score / rank / dd / lu20 | Signal 上的 **派生快照 Property**（从 DailyBar 拷贝，标明 Function 与 Strategy.version） |
| status | **决策 Property**（Action） |
| `rankUniverse` / `scoreV2` / `computeLiveRanks` | **Function** |
| 每晚生成 Signal 对象 | **Pipeline Schedule** 调 Function，不是 Action |
| ApproveSignal | **Action** |

禁止：把 456 只当天的分数做成 456 个 Stock 上的 `todaysScore`（时间机器 + 污染身份对象）。分数属于 **这一天的 Signal 或 DailyBar**。

## 本步需要的数据

- 当日全池 DailyBar（含足以算 f1–f4 的字段）。
- 当日 TradingDay（制度可稍后写，但打分前必须有）。
- 启用中的 Strategy。
- 股票池成员（Index links）。

获取过程 → 05（制度）→ 06（DailyBar 指标）→ 07（下载）。

## 技能与校验

- Skill：`trading-research`（只许用卡片上的 f1–f4 权重）、`tdd`（同一 456 条 bar 两次 `computeLiveRanks` 位次一致）。
- 校验：Signal.primaryKey = `strategyId:date:ticker`；同一日同一策略同一股票不能两条。
