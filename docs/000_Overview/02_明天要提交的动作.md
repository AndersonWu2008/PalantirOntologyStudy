# 02 — 明天要提交的动作

## 思考

产物 A 是「明天可执行」。在 Palantir 里，可执行 = **Action type**：一次提交，改一批对象。

不要先设计表。先列出交易员明天早上手会点的那几下。

A 股 T+1：T 日收盘后准备，T+1 开盘附近提交（涨停买不进等约束在提交条件里检查）。

## 明天可能发生的提交

| 交易员意图 | Action type | 提交后 Ontology 变成什么 |
|------------|-------------|--------------------------|
| 这张早盘卡可以做 | `ApproveSignal` | Signal.status → approved（决策 Property） |
| 这张卡不做 | `RejectSignal` | rejected + reason |
| 按权重买 | `SubmitBuyOrder` | 新建 Order，可能新建 Position；链到 Signal、Stock、Account |
| 卖掉/减仓 | `SubmitSellOrder` / `ReducePosition` / `ClosePosition` | Order + 改 Position |
| 撤单 | `CancelOrder` | Order.status |
| 今日不再新开 | `PauseTrading` | Account 或 Strategy 上的决策 Property |

这些 Action 必须是**业务操作**（一笔买单），不是 `SetClosePrice`（Golden Hammer / Action sprawl）。

## 停：分类

| 念头 | 判定 |
|------|------|
| Approve / SubmitBuy / Close… | **Action type** |
| 一次买单 | **Order** object type |
| 一笔成交回报 | **Fill** object type（券商事实，偏源 Property：价格数量时间） |
| 账户里还拿着的那一段持仓 | **Position** object type |
| 「建议买 20%」这个数字 | 先是 Function `sizePosition` 的输出；写入 Order 时变成该 Order 的 Property（决策快照） |
| 收盘价 | **还不是本步的对象**；它是提交条件要**读**的数，下一章才追溯 |

## 本步需要哪些数据（仍未下载）

每个 Action 的 **submission criteria** 要读：

- 账户现金、是否暂停 → Account
- 是否已持仓、行业已有几只 → Position + Industry link
- 这只股票是否 ST、是否今日涨停 → Stock + 当日 DailyBar（DailyBar 下一章才有资格出现）
- 门控是否打开 → Function `gateOpen`（读 TradingDay + Strategy）
- 用哪套参数 → Strategy

因此：**没有 Account / Position / Order / Signal / Strategy，明天的 Action 无处落笔。** 它们不是「以后再加的模块」，是目标的一部分。

Fill 来自券商回报，不是算出来的。那是源数据，推到 07、09。

## 技能与校验

- Skill：`prototype`（用假 Signal 点一遍批准→下单，看缺哪些对象）。
- 校验：每个 Action 能否说出「改哪些对象、失败时凭哪条 Function」；没有「改一个单元格」式的 Action。
